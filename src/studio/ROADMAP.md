# ROADMAP — qtclass-studio

> 定位：**教学现场**——教师与管理者的主动操作端。派任务、盯进度、批作业、跑淘汰赛。三端分工总纲见仓库根 [ROADMAP.md](../../ROADMAP.md)。

## 方向变更（2026-11-01）

原「互动影游式课程引擎」转型路线废止，但按反馈教学口径回收：影游的本体不是播放器，是**分解表**——把一门课拆成反馈单元序列，每个单元四件套：小需求、学员动作、判定、反馈，判定和反馈当场给。载体归 lite，分解表（单元结构与反馈语）是内容与标准，归课程云。

- 播放器**保留并升级为预览能力**，不移除：教师发布单元序列前预览、课堂现场直接跑；面向学员的正式交付端在 lite，两端按同一数据契约各持一份实现
- 学员登录、学习入口冻结不加新，lite v0.1 落地后再定去留
- 页面规格 `doc/screens/` 是 lite 交付端的蓝本，studio 侧继续维护（上游已断）
- 过渡用法：迁出前教师可直接用现有播放器在课堂上跑单元序列（冻结的是加新功能，不是停用）——教师在场，学员选完即时讨论，这是单元的教学时刻

## 现状

Flutter（v0.1.9 已发布，部署 `studio.class.quanttide.com`）：课表、课堂、课时详情、互动播放器；学员登录接 qtcloud-auth；「学习」入口展示训练营/任务/完成状态。旧进度上报与立项入口（`/progress`、`/proposals`）已暂停，上游在学习云重构中移除。

## 规划

### v0.2 — 教学现场最小闭环（下一步）

教师每天只在 studio 完成「派任务 → 收交付 → 反馈」：

- [ ] 任务派发：面向班级 / 学员，带截止与验收标准
- [ ] 交付收取与批改：评语、退回重做、通过
- [ ] 学员侧收敛：登录、学习入口冻结（不再加功能）；播放器升级为预览能力（见下）
- [ ] 播放器预览能力：教师发布单元序列前在 studio 预览全流程，课堂现场直接跑

数据面依赖：[provider](../provider/ROADMAP.md) 的任务链路，前置是学习云任务模型重建。在上游就绪前，v0.2 用静态数据先跑通流程，接口形状按 provider 契约留好。

### v0.3 — 淘汰赛与进度

- [ ] 班级进度视图：谁在推进、谁掉队
- [ ] 淘汰流程：触发、记录、通知

### 达成标志

v0.2：教师布置一次任务到收到批改反馈，全程不离开 studio。
v0.3：一眼看出本班谁掉队，淘汰有据可查。
