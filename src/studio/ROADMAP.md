# ROADMAP — qtclass-studio

> 定位：**教学现场**——教师与管理者的主动操作端。派任务、盯进度、批作业、跑淘汰赛。三端分工总纲见仓库根 [ROADMAP.md](../../ROADMAP.md)。

## 方向变更（2026-11-01）

原「互动影游式课程引擎」转型路线废止。教学的本体是**任务循环**——小需求、学员动作、判定、反馈，判定和反馈当场给。学员在做，不在看，所以不需要播放器：影游残余的三样东西并入任务词汇——单元序列变任务列表（有序、过门槛），播放状态机变任务状态（待做/进行/已交/退回/通过），视频场景变题面里可嵌的素材。

- 播放器**降级**：编排架构（`widgets/stage/`、`player_state.dart`、`segment/interaction/choice_option` 模型）废弃，不再升级；题面媒体组件（`video_scene` 等嵌入件）保留，任务详情里可嵌播放
- 预览能力转为**任务流预览**：教师发布前在 studio 过一遍任务列表与题面，课堂现场直接投影任务
- 学员登录、学习入口冻结不加新，lite v0.1 落地后再定去留
- 页面规格 `doc/screens/` 是 lite 任务页面的蓝本，studio 侧继续维护

## 现状

Flutter（v0.1.9 已发布，部署 `studio.class.quanttide.com`）：课表、课堂、课时详情、互动播放器（上述降级对象）；学员登录接 qtcloud-auth；「学习」入口展示训练营/任务/完成状态。旧进度上报与立项入口（`/progress`、`/proposals`）已暂停，上游在学习云重构中移除。

## 规划

### v0.2 — 教学现场最小闭环（下一步）

教师每天只在 studio 完成「派任务 → 收交付 → 反馈」：

- [ ] 任务派发：面向班级 / 学员，带截止与验收标准；课程即任务序列（仓内数据编排）
- [ ] 交付收取与批改：评语、退回重做、通过；AI 即时判自由作答，教师异步批改兜底
- [ ] 任务流预览：教师发布前过一遍任务列表与题面（含嵌入媒体）
- [ ] 学员侧收敛：登录、学习入口冻结（不再加功能）；播放器编排架构随任务化废弃

数据面依赖：[provider](../provider/ROADMAP.md) v0.2 任务链路（上游已脱钩，仓内自持，不再等学习云）。在 provider 就绪前，v0.2 用静态数据先跑通流程，接口形状按 provider 契约留好。

### v0.3 — 淘汰赛与进度

- [ ] 班级进度视图：谁在推进、谁掉队
- [ ] 淘汰流程：触发、记录、通知

### 达成标志

v0.2：教师布置一次任务到收到批改反馈，全程不离开 studio。
v0.3：一眼看出本班谁掉队，淘汰有据可查。
