# ROADMAP — qtclass-studio

教学设计工作台，**单用户**：你作为老师设计教学方案——任务设计（对象 / 分解 / 判断标准）、脚手架沉淀、教学动作注解、任务书生产线。无学员面、无客户面：学员的一切在 lite。

现状：Flutter，v0.1.9 已发布（`studio.class.quanttide.com`）。

## 核心判断：v0.1 的互动编排引擎是本体

studio v0.1 的资产不是页面，是**互动引擎**——节点带交互与选择的编排模型（`segment / interaction / choice_option` 那套结构）。任务系统的节点上**暂时装的是文档**（任务书、题面），不是视频——视频只是载荷之一，换载荷不动模型。创作空间设计的正是这些节点：分解树的「阶段→动作→检查点」、教学动作元数据，都挂在这套节点模型上。

冻结的是**学员消费壳**（登录、学习入口、播放器页面）；引擎模型保留为设计对象，不清理。

## 精简理由（学员交互与客户面整体砍除）

- **没有第二个人**：studio 目前唯一使用者是设计者本人。派任务、批改、客户查看、淘汰赛，全是为不存在的使用者做界面——工程花在假设上
- **学员交互已有归宿**：学员在 lite（在做不在看）；客户消费的是数据不是界面。退场不产生用户损失
- **退场 ≠ 永久删除**：开真实教学班、客户要看交付时，按届时需要回补；lite 与 provider 的接口缝不受影响

## 下一步待办（设计工作台）

### 教学创作空间（源自洞察仓 studio.md，新思路优先）

- [ ] Assignment（大作业）：数据契约三字段——`id`（uuid）/ `title` / `content`；content 当前装 Markdown 长文本（任务书全文），未来拓展视频等格式；解体与教学动作挂 id
- [ ] 分解树：阶段 → 动作 → 检查点，每个动作带可核对的判断标准（不是"写完"，是"开头 300 字内有明确冲突"）；设计态预览并入本视图
- [ ] 脚手架库：前置思考题、常见坑点、示例反例、反思触发器——教学经验固化为可复用组件
- [ ] 教学动作元数据：每步挂"老师为什么这么安排"，产出经契约给 lite 展示（studio 本身不面向学员）
- [ ] 修订回环（任务书生产线）：首任务 = 任务书修订，AI 预筛 diff，教师合稿回灌仓内任务书、按修订重排任务序列——教研嵌在任务流里，不设独立仪式

不做：权限 / 多人协作、AI 生成任务（先手写 2-3 个完整模板）、可视化拖拽（结构化表单 + Markdown 区块够用）。
