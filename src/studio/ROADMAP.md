# ROADMAP — qtclass-studio

教学与管理工作台：你作为设计者与管理者，设计教学方案、运营班级；**用户 = 自己 + B端/G端**（后两者只读，看交付与活跃的账）。v0.1 的「单用户、无客户面」判断建立在当时没有第二个人的前提上，前提在 v0.2.0 变了，定位随之改写；学员交互仍然全部在 lite，这条不变。

分解一题一答：**lite 的分解是对象正本**——course / lesson / task / cohort / example 已上线，一字不动；studio 只建 lite 刻意不建的对象（学员、学习记录、评审结论）和挂在对象上的状态与动作。内部管理结构（谁招生、谁评审、流程怎么走）落在角色与动作上，不另立对象目录；B/G 端看同一批对象的投影，不另起目录。

现状：Flutter，v0.1.9 已发布（`studio.class.quanttide.com`）；三件模型已独立实现于 `lib/models/`（toolkit 暂不引入，迭代稳定后固定回 `quanttide-tech-toolkit` 的 `dart/course`）。v0.2.0 设计如本文件，未开工。

## 核心判断：v0.1 的互动编排引擎是本体

studio 的资产不是页面，是**互动引擎**——节点带交互与选择的编排模型（`segment / interaction / choice_option` 那套结构）。任务系统的节点上**暂时装的是文档**（任务书、题面），不是视频——视频只是载荷之一，换载荷不动模型。三件孪生同形（`id`(uuid) / `title` / `content`）：判断标准与注解都写进 content，不设挂件。

冻结的是**学员消费壳**（登录、学习入口、播放器页面）；引擎模型保留为设计对象，不清理。

## 对象归位：三件套与 lite 的关系

- **Assignment = lite `task` 的设计态**：任务书生产线回灌的就是仓内任务书——同一批文件，studio 是设计面
- **Solution / SolutionStep = lite `lesson` 的设计态**：参考与步骤的载体，`after` 链的投影语义就是 lite 的过门槛
- 模型名是否改成与 task / lesson 对齐——**命名归用户**；v0.2.0 先在模型注释里写死对应关系，不动名字

## 管理层新对象（lite 刻意不建的三件）

**Learner 学员**——班级归属、参与度四级（没有参与 / 以玩家参与 / 以作者产出 / 以指导者帮助）、在读与退出状态。

**LearningRecord 学习记录**——关联学员与任务，沿三件套规矩 `id / title / content` 孪生；四要素（做了什么 / 遇到什么卡点 / 怎么解决 / 待完善点在哪）写进 content，不为要素发明字段。

**Review 评审结论**——关联学员与班级，结论三分（录取实训基地 / 留作免费学员 / 退出班级），依据指向学习记录；淘汰与分流是记账，不是赛事界面。

## 班级状态动作

cohort 是 lite 正本，studio 是它的编辑面：招生中 → 进行中 → 已结课的状态迁移，开班日期、限额、报名窗口的改写——变更走修订回环同款回灌通道回仓内文件，不新开存储。

## 精简理由（v0.1 判断，留档）

> 前提（单用户）在 v0.2.0 已变：管理层与 B/G 只读投影回归，学员交互仍归 lite。以下为 v0.1 当时的判断，留档防断章取义。

- **没有第二个人**：studio 当时唯一使用者是设计者本人。派任务、批改、客户查看、淘汰赛，全是为不存在的使用者做界面——工程花在假设上
- **学员交互已有归宿**：学员在 lite（在做不在看）；客户消费的是数据不是界面。退场不产生用户损失
- **退场 ≠ 永久删除**：开真实教学班、客户要看交付时，按届时需要回补；lite 与 provider 的接口缝不受影响
