# 熟悉数据工程第二大脑

我们有一份《量潮数据工程》领域仓库（quanttide-data），内部团队正在陷入「知识的诅咒」——我们很难判断现有的知识结构对没有上下文的新人来说是否足够友好。我们想请你以新人的视角走一遍，把真实的感受带回来，帮助我们把第二大脑体系打磨得更容易被下一个人理解。

## 第一步：熟悉领域第二大脑体系

1. 通读领域主仓库：https://github.com/quanttide/quanttide-data ，理解它的子模块架构（data/ 陈述性记忆、docs/ 程序性记忆、apps/ 应用、examples/ 实验室、packages/ 工具包）
2. 阅读两篇参考资料，它们定义了第二大脑的资产图式与发布流程：
   - 量潮第二大脑资产图式章程：https://github.com/quanttide/quanttide-bylaw-of-asset-management/blob/main/schema/second-brain.md
   - 量潮发布管理章程：https://github.com/quanttide/quanttide-bylaw-of-devops/blob/main/lifecycle/release.md
3. 边了解边记录困惑：哪些结构一目了然？哪些地方没有上下文根本看不懂？哪些说明与实际不符？

## 第二步：通过 Issue 和 PR 提出改进建议

讨论与产出提交到量潮数据工程主仓库：https://github.com/quanttide/quanttide-data

社区协作流程如下：

1. 在 Issue 中提出你的想法，与团队讨论达成共识
2. 共识后提交 PR，并在 PR 中引用该 Issue
3. PR 通过后关闭 Issue

我们以通过的 PR 的价值来计算敏捷故事点，具体规则需要一起摸索——你的每一次贡献都会为后来人建立一套「宪法判例」。

## 重要提醒

- 参考资料归属其他第二大脑（资产管理、devops），你同样可以在那些仓库提出类似的改进建议
- 不需要一次性给出完美方案，先抛出真实感受，再完善细节

如果在操作中遇到任何问题（比如不知道怎么开 Issue、PR），随时在群里或邮件问我，我会一步步引导。让我们一起把第二大脑体系打磨得更好用！
