# 文档工程章程

我们有一份《文档工程格式章程》，用来统一团队文档的写法。现在我们想请你把真实感受带进来，帮我们把这份章程升级成“社区版”，方便你未来直接复用，也让其他人受益。

第一步：在 Issue 中分享你的想法（必须先做）

1. 熟悉并试用现有章程内容：  https://github.com/quanttide/quanttide-bylaw-of-document-engineering/blob/main/format/index.md

2. 对照章程，想一想：
   - 哪些规则你用起来很顺手？
   - 哪些地方让你困惑、觉得不适用，或者可以更清晰？
   - 你自己写文档时有哪些好习惯，觉得应该加进去？

3. 把你的想法写到对应的 Issue 讨论区里：  https://github.com/quanttide/quanttide-bylaw-of-document-engineering/issues/1
   - 点击页面底部的“Comment”框，用大白话写下你的建议、困惑或具体例子。  
   - 如果怕说得不完整，哪怕只有一两句话也完全没问题。  
   - 这一步是必须的，因为我们要先通过讨论达成共识，再动手改文件。

第二步：根据讨论结果提交 PR（修改草案）

在 Issue 讨论达成初步共识后，你需要把最终确定的修改内容落实到章程文件里，并提交一个 Pull Request（PR）。

- 如果你熟悉 Git 和 GitHub 操作，可以直接修改 `index.md` 文件，然后创建 PR。
- 如果你对 PR 操作还不熟悉，**不用紧张**——你可以在 Issue 中说明自己不会操作，我们会安排人或陪你一起完成这一步，或者由你口述修改内容，我们帮你代劳提交 PR。

但请记住：**提交 PR 之前，一定要先经过 Issue 讨论**，确保修改是有共识的，而不是个人随意的改动。

重要提醒：
- 整个过程不需要你一次性给出完美方案。先抛出想法，再完善细节。
- 预计第一步耗时 10~15 分钟，第二步视情况而定，但如果不会操作，我们会协助，不用有压力。
- 你的每个意见都很宝贵，因为它是来自真实实践的第一手反馈。

如果在操作中遇到任何问题（比如找不到评论按钮、不知道怎么开 PR），随时在群里或邮件问我，我会一步步引导。让我们一起把章程打磨得更好用！
