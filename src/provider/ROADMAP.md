# ROADMAP — qtclass-provider

数据面，应用侧集成层：下游 Studio / Lite / Site，上游仓内自持（脱钩课程云 / 学习云，客户端契约不变，留回归缝）。

**v0.1 里的角色 = 契约的落笔处之一，但接口不超前。** 模型未定不浇筑——本阶段只做两件事：把任务链路的模型定义收敛进一版契约，保持既有骨架运行。契约定型后，下方任务链路照契约施工。

已交付（运行中）：服务骨架、播放器数据组装、完成回写、FC 部署管道；`/progress`、`/proposals` 上游已断，studio 对应功能暂停。

## v0.1：模型定义进契约（不铺接口）

- [ ] **任务书与任务实例分离**：任务书仓内版本化（修订 = 分叉、合稿 = 裁决），实例 = 派发记录——修订不改实例、回灌不丢轨迹。这是模板 / 实例第一刀在本仓的落点
- [ ] **状态表即流程定义**：五状态迁移逐个接口守卫，不允许绕过
- [ ] **criterion 挂载**：每任务一条判定；判定与反馈是实例侧事件，挂实例不挂任务书
- [ ] **仓内自持三线定形**：内容数据文件进仓（与 site 同源）、自带存储（learner × criterion）、任务模型仓内定义（契约按 studio 静态数据先行验证）
- [ ] **真实业务约束进契约**：任务关联订单来源；交付前经不同机器 / 系统验证；报名为周期性意愿确认；记录行动与其效果的对应关系

## 契约后：任务链路照契约施工

「任务下发 → lite 取任务 → 交付 → 回写」经本服务即全部，客户端仍单依赖（studio 已单用户化，不设派发界面）：

- [ ] 任务下发：任务实例 → lite 拉取（按 learner 投影今日任务卡）
- [ ] 交付提交：lite 提交 → studio 批改面收取
- [ ] 任务状态回写：派发 / 提交 / 退回重做 / 通过，落仓内任务模型
- [ ] 单元并入任务：课程 = 任务序列，任务 = 小需求 + 动作 + 判定 + 反馈

## 云回归（回灌）

- 触发：云模型稳定 + 第二个消费者出现（训练营独立售卖、企业培训接入）
- 回灌：内容迁回课程云、账本迁回学习云、任务模型对齐新契约；回归缝 = 客户端契约不变，应用侧零改动
- 仓内期间缓存纪律：仓内是缓存不是事实源，带出处、可重建，回灌以云为准
- 学习云起步路径（回归后）：整合内容生产工具链 → HTML 教学原型试效果 → 蓝图试效果 → 基础数据就绪后链路跑通
