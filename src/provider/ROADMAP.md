# ROADMAP — qtclass-provider

> 定位：qtclass 的应用侧集成层。下游服务 Studio / Lite / Site。**2026-11-01 起暂时取消对课程云 / 学习云的依赖，上游改仓内自持**：内容以数据文件进仓、账本自带存储；对客户端的组装/回写契约不变，留回归缝，回归条件见「云回归」。设计沿用 `docs/dev-guide/provider.md`（id 同源直连、应用层零关联表）。三端分工总纲见仓库根 [ROADMAP.md](../../ROADMAP.md)。

## 已交付（v0.1）

1. **播放器数据组装**——把课程内容实体转换为 Studio 播放器契约（segments/pathSteps 与 criteria 关联组下发）
2. **完成回写**——验收判定落为学习云 Completion 记录（learner × criterion 幂等，白名单校验 criterion_id）
3. 服务骨架 + FC 部署管道（质量门禁前置）；学习云代理：`/completions`、`/progress`、`/proposals` 经本服务转发，客户端单依赖本服务

```
        课程云（内容+标准事实源）            本服务                学习云（记录面）
   Course/Lesson/Scene ─ 内容实体 → [播放器组装] → segments/pathSteps/criteria 下发
   Criterion 定义      ─ 交付判定语义 ↘        │
                                           ↓
Studio 验收达成 ─────────────────→ [完成回写] ────→ Completion（learner × criterion）
```

> （v0.1 直连形态；脱钩后上游换为仓内自持，客户端契约不变。）
>
> 注：`/progress`、`/proposals` 上游已在学习云重构中移除，studio 对应功能已暂停，待任务链路立项时按新契约重建。

## 规划

### v0.2 — 任务链路（应用侧的全部数据面）

播放器降级为任务管理系统后，「studio 派任务 → lite 取任务 → 交付 → 回写」经本服务即全部，客户端仍单依赖：

- [ ] 任务下发：studio 派发（班级/学员、截止、验收标准）→ lite 拉取（按 learner 投影今日任务卡）
- [ ] 交付提交：lite 提交交付物 → studio 批改面收取
- [ ] 任务状态回写：派发 / 提交 / 退回重做 / 通过，落仓内任务模型
- [ ] 单元并入任务：反馈单元不另立实体——课程=任务序列，任务=小需求+动作+判定+反馈；每任务挂一条 criterion 回写完成记录

前置改为**仓内自持**，不再等上游：

- 内容线：课程内容数据文件进仓（与 site `data/learning/` 同源，三端读同一份），组装从仓内文件出；criteria 定义随内容走
- 账本线：provider 自带存储，learner × criterion 结构不变
- 任务模型：仓内自持（派发 / 提交 / 退回重做 / 通过），契约形状按 studio v0.2 的静态数据先行验证

### v0.3（远期）— 统一聚合入口

Studio / Lite / Site 的所有上游调用收敛至本服务，缓存策略视流量引入；先有真实痛点再立项。

### 云回归（回灌）

- 触发条件：课程云 / 学习云模型稳定，且出现第二个消费者（如训练营独立售卖、企业培训接入）
- 回灌范围：仓内课程内容迁回课程云，账本迁回学习云，任务模型对齐学习云新契约；回归缝即客户端契约不变，应用侧零改动
- 仓内期间的缓存纪律：仓内课程数据是缓存不是事实源——带出处、可由上游重建；回灌时以云为准
