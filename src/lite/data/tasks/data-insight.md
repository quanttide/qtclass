# 整理数据工程洞察

数据工程的语境资料（context）主要来自与 AI 协作过程中产生的随手记录。相比于有结构有条理的日志，语境资料要脏很多。我们想请你把它们梳理成关键洞察。

## 洞察的定位

洞察是「未来的语义记忆」，它们最大的特点是可以迁移——可以从一个领域迁移到另外一个领域，也可以从一个组织迁移到另外一个组织。这是未来知识体系的核心出发点。

## 参考与建模

洞察目前还没有成型的结构。建议参考数据工程教程和札记（这是洞察未来主要的升级方向之一）。搭建信息结构也是非常重要的一课，希望你可以尝试一下，通过你的 Issue 和 PR 和我们沟通你的建模想法。

## 步骤

1. 阅读数据工程语境资料：https://github.com/quanttide/quanttide-context-of-data-engineering
2. 参考数据工程教程与札记：https://github.com/quanttide/quanttide-tutorial-of-data-engineering 、https://github.com/quanttide/quanttide-essay-of-data-engineering
3. 梳理出关键洞察，并按下方提交方式与团队沟通你的信息结构建模想法

## 提交方式

讨论与产出提交到数据工程洞察仓库：https://github.com/quanttide/quanttide-insight-of-data-engineering

1. 先在 Issue 中提出你的想法，与团队讨论达成共识
2. 共识后提交 PR，并在 PR 中引用该 Issue
3. PR 通过后关闭 Issue

如果你对 Issue 和 PR 操作不熟悉，不用紧张——在 Issue 中说明自己不会操作即可，我们会安排人或陪你一起完成这一步。
